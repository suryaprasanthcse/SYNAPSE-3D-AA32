## 2. Visual mechanics

**Custom GPU compute boids.** Petalo's swarm is simulated entirely on the GPU by
`SwarmCompute.compute` (thread group 64) across six kernels per frame: clear grid, hash boids,
bitonic sort (global and local passes), build grid, and the boids update that also writes per-agent
transforms. Rendering is a single `Graphics.RenderMeshIndirect` call reading those transforms from a
structured buffer, so there are no per-agent GameObjects and no CPU readback. At the shipped
tabletop profile this is about 0.14 MB of GPU buffers and 7 dispatches per frame.

**HDR emission and bloom, not lights.** Puzzle state is carried by the swarm's HDR rim emission,
multiplied by an emission-intensity factor (4.0) so it crosses the URP Bloom threshold and radiates.
The AR scene uses **no point lights and no spot lights**; a single directional light provides base
shading, and the glow is entirely emissive plus post-processing. This keeps per-frame lighting cost
flat and protects mobile thermals, at the cost of one full-screen post-processing pass that the
controller enables on the AR camera at start-up.

**Runtime systems.** `ARTrackedImageManager` (5 reference images, 5 moving images) →
`ARMultiMatrixPayload` (image-to-hologram routing, keyed by TrackableId) → `ARBoidBridge` (spawns,
pauses and rebuilds the swarm on the anchor card) → `PuzzleStateController` (proximity, yaw and the
cyan-to-gold state machine).

the build is either a Unity primitive or generated by our own editor scripts. Usage rights for the
Funobotz kit imagery (Petalo and the five card faces) follow from the hackathon-provided material;
the team is confirming the exact terms before any public release.

## 4. AI usage declaration

AI assistance (**Anthropic Claude**, via Claude Code) was used as a development co-pilot under team
direction. To be fully transparent, it contributed in four areas:

1. **Editor workflow automation** — build configuration, AR rig assembly, target injection, asset
   cleanup, screenshot capture and documentation generation scripts.
2. **Runtime gameplay scripting** — first drafts of `ARMultiMatrixPayload`, `ARBoidBridge` and
   `PuzzleStateController`, written against our existing swarm engine and reviewed by the team.
3. **Diagrams and mockups** — the top-down environment map and the UI/feedback mockups used in
   Phase 2 documentation were generated programmatically with AI assistance.
4. **Documentation** — drafting and formatting of the Phase 2 and Phase 3 written deliverables.

**Design ownership, architecture decisions, tuning values and all acceptance of generated code
remained with the team.** No AI-generated art, audio or 3D models ship in the build; the only
AI-assisted imagery appears in documentation, and is labelled as such where it is used.
